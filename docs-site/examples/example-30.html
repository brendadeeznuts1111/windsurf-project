# 🧪 Bun Testing Guide

*Generated on 2025-12-12T14:35:00.000Z*

## 📋 Overview

Bun provides a comprehensive testing framework built on top of Jest's API, with enhanced performance and Bun-specific features. This guide covers the testing structure, running tests, writing tests, and best practices for the Bun codebase.

## 🗂️ Test Organization

Tests are located in the `test/` directory and organized by functionality:

### Main Test Directories

- **`test/js/`** - Tests for JavaScript APIs
  - **`bun/`** - Bun-specific APIs (`Bun.serve`, `Bun.file`, etc.)
  - **`node/`** - Node.js APIs (`fs`, `path`, `crypto`, etc.)
  - **`web/`** - Web APIs (`fetch`, `WebSocket`, `URL`, etc.)
  - **`first_party/`** - Built-in npm packages (`undici`, etc.)
  - **`third_party/`** - Popular third-party packages (`esbuild`, etc.)

- **`test/cli/`** - Tests for CLI commands, configurations, and stdout
- **`test/bundler/`** - Tests for transpiler/bundler functionality
- **`test/regression/`** - Tests that reproduce specific issues
- **`test/harness.ts`** - Utility functions for all tests

## 🏃 Running Tests

To run a test, use Bun's built-in test command: `bun test`.

```bash
bun test # Run all tests
bun test js/bun # Only run tests in a directory
bun test sqlite.test.ts # Only run a specific test
```

If you encounter lots of errors, try running `bun install`, then trying again.

## ✍️ Writing Tests

Tests are written in TypeScript (preferred) or JavaScript using Jest's `describe()`, `test()`, and `expect()` APIs.

```typescript
import { describe, test, expect } from "bun:test";
import { gcTick } from "harness";

describe("TextEncoder", () => {
  test("can encode a string", async () => {
    const encoder = new TextEncoder();
    const actual = encoder.encode("bun");
    await gcTick();
    expect(actual).toBe(new Uint8Array([0x62, 0x75, 0x6E]));
  });
});
```

If you are fixing a bug that was reported from a GitHub issue, remember to add a test in the `test/regression/` directory.

```typescript
// test/regression/issue/02005.test.ts

import { it, expect } from "bun:test";

it("regex literal should work with non-latin1", () => {
  const text = "这是一段要替换的文字";
  expect(text.replace(new RegExp("要替换"), "")).toBe("这是一段的文字");
  expect(text.replace(/要替换/, "")).toBe("这是一段的文字");
});
```

In the future, a bot will automatically close or re-open issues when a regression is detected or resolved.

## 🦎 Zig Tests

These tests live in various `.zig` files throughout Bun's codebase, leveraging Zig's builtin `test` keyword.

Currently, they're not run automatically nor is there a simple way to run all of them. We will make this better soon.

## 🔷 TypeScript

Test files should be written in TypeScript. The types in `packages/bun-types` should be updated to support all new APIs. Changes to the `.d.ts` files in `packages/bun-types` will be immediately reflected in test files; no build step is necessary.

Writing a test will often require using invalid syntax, e.g. when checking for errors when an invalid input is passed to a function. TypeScript provides a number of escape hatches here.

- `// @ts-expect-error` - This should be your first choice. It tells TypeScript that the next line *should* fail typechecking.
- `// @ts-ignore` - Ignore the next line entirely.
- `// @ts-nocheck` - Put this at the top of the file to disable typechecking on the entire file. Useful for autogenerated test files, or when ignoring/disabling type checks an a per-line basis is too onerous.

## 🧪 Test Types & Patterns

### API Testing
```typescript
describe("Bun.file", () => {
  test("reads text files", async () => {
    const file = Bun.file("test.txt");
    const text = await file.text();
    expect(text).toContain("expected content");
  });

  test("handles missing files", async () => {
    const file = Bun.file("nonexistent.txt");
    expect(file.exists()).toBe(false);
  });
});
```

### CLI Testing
```typescript
import { spawn } from "bun";

describe("CLI commands", () => {
  test("version command", async () => {
    const proc = spawn(["bun", "--version"], {
      stdout: "pipe",
      stderr: "pipe"
    });

    const output = await proc.stdout.text();
    expect(output).toMatch(/\d+\.\d+\.\d+/);
  });
});
```

### Web API Testing
```typescript
describe("fetch", () => {
  test("makes HTTP requests", async () => {
    const response = await fetch("https://httpbin.org/json");
    const data = await response.json();
    expect(data).toHaveProperty("test");
  });
});
```

### Memory Testing
```typescript
test("no memory leaks", async () => {
  const initialMemory = process.memoryUsage().heapUsed;

  // Perform operations
  for (let i = 0; i < 1000; i++) {
    const data = new Array(1000).fill("test");
    await gcTick();
  }

  const finalMemory = process.memoryUsage().heapUsed;
  expect(finalMemory - initialMemory).toBeLessThan(1024 * 1024); // < 1MB increase
});
```

## 🔧 TypeScript in Tests

### Type Checking Options

- **`// @ts-expect-error`** - Preferred for intentional type errors
- **`// @ts-ignore`** - Ignore type checking for a line
- **`// @ts-nocheck`** - Disable checking for entire file

### Example: Testing Error Conditions
```typescript
describe("error handling", () => {
  test("throws on invalid input", () => {
    // @ts-expect-error - intentionally passing wrong type
    expect(() => Bun.file(123)).toThrow();
  });

  test("handles edge cases", () => {
    // @ts-ignore - testing runtime behavior despite types
    const result = someFunction(undefined);
    expect(result).toBeDefined();
  });
});
```

## 🏗️ Build & Bundle Testing

### Transpiler Tests
```typescript
describe("TypeScript transpilation", () => {
  test("handles modern syntax", () => {
    const code = `
      const arrow = (x: number) => x * 2;
      const optional: string | undefined = "test";
    `;

    const result = Bun.build({ code, target: "browser" });
    expect(result.success).toBe(true);
  });
});
```

### Bundle Testing
```typescript
describe("bundler", () => {
  test("creates valid output", async () => {
    const result = await Bun.build({
      entrypoints: ["./src/index.ts"],
      outdir: "./dist",
      target: "bun"
    });

    expect(result.success).toBe(true);
    expect(result.outputs.length).toBeGreaterThan(0);
  });
});
```

## 🧪 Advanced Testing Patterns

### Performance Testing
```typescript
describe("performance", () => {
  test("fast execution", async () => {
    const start = performance.now();

    // Perform operation
    const result = expensiveOperation();

    const end = performance.now();
    expect(end - start).toBeLessThan(100); // < 100ms
  });
});
```

### Concurrent Testing
```typescript
describe("concurrency", () => {
  test("handles parallel requests", async () => {
    const promises = Array.from({ length: 10 }, () =>
      fetch("https://api.example.com/data")
    );

    const results = await Promise.all(promises);
    expect(results.every(r => r.ok)).toBe(true);
  });
});
```

### WebSocket Testing
```typescript
describe("WebSocket", () => {
  test("connects and communicates", async () => {
    const ws = new WebSocket("ws://localhost:3000");

    await new Promise(resolve => {
      ws.onopen = resolve;
    });

    ws.send("test message");

    const message = await new Promise(resolve => {
      ws.onmessage = (event) => resolve(event.data);
    });

    expect(message).toBe("echo: test message");
    ws.close();
  });
});
```

## 🐛 Zig Tests

Zig tests use Zig's built-in `test` keyword:

```zig
const std = @import("std");

test "basic functionality" {
    const result = someFunction();
    try std.testing.expect(result == expected);
}
```

## 🔧 Best Practices

### 1. **Descriptive Test Names**
```typescript
// ✅ Good
test("throws error when file does not exist", () => { ... });

// ❌ Bad
test("file error", () => { ... });
```

### 2. **Arrange-Act-Assert Pattern**
```typescript
test("calculates total correctly", () => {
  // Arrange
  const items = [{ price: 10 }, { price: 20 }];

  // Act
  const total = calculateTotal(items);

  // Assert
  expect(total).toBe(30);
});
```

### 3. **Test Isolation**
```typescript
describe("Database", () => {
  let db: Database;

  beforeEach(() => {
    db = createTestDatabase();
  });

  afterEach(async () => {
    await db.close();
  });

  test("saves data", async () => {
    await db.save({ id: 1, name: "test" });
    const result = await db.find(1);
    expect(result.name).toBe("test");
  });
});
```

### 4. **Mock External Dependencies**
```typescript
import { mock, spyOn } from "bun:test";

test("fetches user data", async () => {
  const mockFetch = mock(() =>
    Promise.resolve({ json: () => ({ id: 1, name: "John" }) })
  );

  spyOn(global, "fetch").mockImplementation(mockFetch);

  const user = await getUser(1);
  expect(user.name).toBe("John");
});
```

### Memory Leaks in Tests
```typescript
test("no memory leaks", async () => {
  const initialHeap = process.memoryUsage().heapUsed;

  // Your test code here
  const largeArray = new Array(1000000).fill("test");

  // Force garbage collection
  await gcTick();

  const finalHeap = process.memoryUsage().heapUsed;
  expect(finalHeap - initialHeap).toBeLessThan(1024 * 1024); // < 1MB
});
```

```typescript
test("handles slow operations", async () => {

```

```typescript
test("file operations", async () => {
```
